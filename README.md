# Таза Қызылорда

Прототип системы экологического мониторинга и управления зелёным фондом.
Хакатон 2026, кейс 01 «Таза Қазақстан — Таза Қызылорда».

Система объединяет обращения жителей о свалках и зелёных насаждениях и объекты зелёного фонда на одной карте города. Обращение проходит полный цикл: подача → назначение исполнителя и срока → выполнение с фото → проверка оператором.

> Все записи при первом запуске — **тестовые данные**. Это указано в шапке сайта, в карточке каждой записи и в выгрузке CSV. Реальных обращений и персональных данных в системе нет.

## Как запустить

1. Скачайте `index.html`.
2. Откройте файл двойным щелчком в Chrome, Edge или Яндекс Браузере.
3. Нужен интернет: карта, адреса и шрифт загружаются из сети.

Установка программ, сервер и сборка не нужны.

## Как выложить в интернет (бесплатно, 10 минут)

На защите удобнее показывать сайт по ссылке: его можно открыть и на ноутбуке, и на телефоне, а камера и геолокация телефона работают только на сайте с адресом `https://`.

**Вариант 1. GitHub Pages** (заодно закрывает требование «исходный код»)

1. Зарегистрируйтесь на github.com.
2. Создайте новый репозиторий (кнопка **New**), имя, например, `taza-kyzylorda`, тип **Public**.
3. На странице репозитория выберите загрузку файлов (**uploading an existing file**), перетащите `index.html` и `README.md`, нажмите **Commit changes**.
4. Откройте **Settings → Pages**. В блоке **Branch** выберите `main` и папку `/ (root)`, нажмите **Save**.
5. Через 1–2 минуты сайт откроется по адресу `https://ВАШ_ЛОГИН.github.io/taza-kyzylorda/`.

**Вариант 2. Netlify Drop** (быстрее, без репозитория)

1. Положите `index.html` в отдельную папку.
2. Откройте app.netlify.com/drop и перетащите папку в окно браузера.
3. Сайт сразу получит ссылку. Чтобы она не пропала, зарегистрируйтесь там же.

## Соответствие заданию

| Функция из кейса | Где в системе |
|---|---|
| Подача обращения с фото, описанием и геоточкой | Роль «Житель» → кнопка «Сообщить о проблеме». Точка ставится щелчком по карте или по геолокации, адрес определяется автоматически |
| Поиск на карте по категории и статусу | Раздел «Карта»: фильтры слева, поиск по номеру, адресу и описанию, поиск улицы на карте |
| Назначение ответственного и срока | Роль «Оператор» → карточка обращения → «Назначить исполнителя и срок» |
| Подтверждение выполнения фотографией | Роль «Исполнитель» → «Отчитаться о выполнении». Без фото отчёт не отправится. Оператор сравнивает фото «до» и «после» |
| Учёт состояния деревьев и зелёных территорий | Раздел «Зелёный фонд»: реестр, состояние, осмотры, история по каждому объекту |
| Планирование полива, уборки и ухода | Раздел «План ухода»: работы по дням, повторяющийся полив, отметка выполнения |
| Панель: открытые и просроченные задачи, объекты, требующие ухода | Раздел «Панель» |

Пользователи из кейса — житель, оператор, исполнитель, специалист по озеленению — переключаются в строке «Вы работаете как».

## Сценарий показа на 3 минуты

Тот же сценарий встроен в сайт: кнопка «?» в правом верхнем углу.

1. **Житель.** «Сообщить о проблеме» → выбрать «Стихийная свалка» → написать описание → добавить фото → щёлкнуть по карте → «Отправить обращение». Обращение получает номер и появляется на карте.
2. **Оператор.** В карточке нажать «Перейти в роль „Оператор“» → «Назначить исполнителя и срок» → «Назначить».
3. **Исполнитель.** «Перейти в роль „Исполнитель“» → «Принять в работу» → «Отчитаться о выполнении» → фото и комментарий → «Отправить на проверку».
4. **Оператор.** Сравнить фото «до» и «после» → «Принять работу и закрыть». Показать историю обращения внизу карточки.
5. **Озеленитель.** «Зелёный фонд» → открыть аварийное дерево → «Записать осмотр» и «Запланировать работу». Затем «План ухода» → отметить полив выполненным: дата полива в карточке объекта обновится, следующий полив встанет в план сам.
6. **Панель.** Открытые и просроченные обращения, объекты, требующие ухода, нагрузка исполнителей. Кнопка «Выгрузить в CSV» открывается в Excel.

**Приём для показа.** Откройте сайт в двух окнах рядом: слева житель, справа оператор на вкладке «Обращения». Новое обращение появится во втором окне само.

После репетиции нажмите «Вернуть тестовые данные» (в «Панели» или в сценарии показа).

## Как устроено

- **Один файл `index.html`**: разметка, стили и программа на чистом JavaScript, без сборки и без сервера.
- **Карта**: библиотека Leaflet 1.9.4, подложки OpenStreetMap / CARTO и спутниковые снимки Esri.
- **Адреса**: сервис Nominatim (OpenStreetMap) — определение адреса по точке и поиск улиц в границах Кызылорды.
- **Данные**: хранятся в браузере (`localStorage`). Фото уменьшаются до 1000 пикселей по длинной стороне.
- **Просрочка** считается автоматически: обращение со сроком в прошлом и работа по уходу с прошедшей датой помечаются красным и попадают в панель.
- **«Требует ухода»** — объект, у которого состояние «требует ухода» или «аварийное», полив просрочен относительно нормы или есть просроченная работа.

## Что важно сказать честно

- Это прототип. Данные живут в браузере конкретного устройства: обращение, поданное с телефона, не появится на ноутбуке. Два окна на одном компьютере синхронизируются.
- Входа по логину нет: роли переключаются кнопкой, чтобы показать все четыре рабочих места за одну демонстрацию.
- Тестовые точки расставлены в пределах города приблизительно. Положение парка Первого Президента и стадиона им. Г. Муратбаева взято из открытых источников, границы территорий условные. Место любого объекта можно поправить: роль «Озеленитель» → карточка объекта → «Уточнить место на карте».
